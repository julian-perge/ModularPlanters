> Heads up · Gradle doesn't watch the new release scripts, so after a script-only edit `./gradlew test` can report a pass without running their tests.
>
> **Gradle can skip the release script tests**
> - The new release tests run the shell scripts in `tools/`, such as `check-release.sh` and `changelog-section.sh`.
> - Gradle skips tests when nothing it tracks has changed. It tracks the Java code, not the files in `tools/`.
> - If only a script changes, `./gradlew test` can mark the tests "up-to-date" and still print BUILD SUCCESSFUL. Today's run did execute them, because the run before it had failed.
> - So a broken script could pass locally and only show up when you push a release tag. It could also publish the wrong changelog notes.
> - **Fix:** have the main agent tell Gradle to watch `tools/` by adding `inputs.dir("tools")` to the test task. Or run `./gradlew test --rerun-tasks` after you edit a script.
